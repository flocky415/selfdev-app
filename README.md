## 1. Правила Firestore (обов'язково)

Без цих правил базу може читати й змінювати будь-хто, хто знає назву проєкту.

1. Відкрий **https://console.firebase.google.com** і увійди своїм Google-акаунтом.
2. Натисни на картку проєкту **selfdev-47e40**.
3. У лівому меню відкрий **Databases & Storage** (або **Build**) → **Firestore Database**.
4. Угорі сторінки відкрий вкладку **Rules** (Правила).
5. Виділи весь текст у редакторі (`Ctrl+A`) і видали його.
6. Відкрий у проєкті файл **`firestore.rules`**, скопіюй **увесь** його вміст і встав у редактор.
7. Натисни синю кнопку **Publish** (Опублікувати) угорі редактора.
8. Має з'явитися напис про успішну публікацію.

Старі профілі друзів (створені до оновлення, без `ownerUid`) нові правила оновлювати не дозволять — створи профіль у «Друзях» заново, а старі документи в колекції `users` можна видалити на вкладці **Data**.

## 2. Вхід через Google (синхронізація)

Після цього в застосунку в «Ще» → «Щоденник» → картка «☁️ Синхронізація» запрацює кнопка **«Увійти через Google»**.

### 2.1. Увімкнути Google як спосіб входу

1. **https://console.firebase.google.com** → проєкт **selfdev-47e40**.
2. У лівому меню: **Security** → **Authentication**.
   (У старому вигляді консолі — **Build** → **Authentication**.)
3. Угорі відкрий вкладку **Sign-in method** (Способи входу).
4. У списку вже є **Anonymous** (Анонімний) — його **не вимикай**, на ньому працюють «Друзі».
5. Натисни **Add new provider** (Додати постачальника) → у списку обери **Google**.
6. Увімкни перемикач **Enable** (Увімкнути) угорі вікна.
7. **Public-facing name for project** (Назва проєкту, яку бачать користувачі) — впиши `SelfDev`.
8. **Support email for project** (Email підтримки) — обери зі списку свою пошту.
9. Натисни **Save** (Зберегти). У списку провайдерів біля Google має з'явитися **Enabled**.

### 2.2. Дозволити свій домен

1. На тій самій сторінці Authentication відкрий вкладку **Settings** (Налаштування).
2. Ліворуч обери **Authorized domains** (Авторизовані домени).
3. Перевір, що в списку є `localhost` і `selfdev-47e40.firebaseapp.com` — вони там за замовчуванням, **не видаляй їх**.
4. Натисни **Add domain** (Додати домен) і впиши:
   ```
   flocky415.github.io
   ```
   Без `https://`, без `/selfdev-app` і без косої риски в кінці.
5. Натисни **Add** (Додати).

### 2.3. Опублікувати правила

Якщо ще не робив — виконай розділ 1: у `firestore.rules` є блок `userdata/{uid}`, у якому зберігаються синхронізовані дані.

### 2.4. Перевірка

1. Відкрий сайт → «Ще» → «Щоденник» → «☁️ Синхронізація» → **Увійти через Google**.
2. Відкриється вікно Google — обери акаунт.
3. У картці має з'явитися `✅ твоя@пошта` і «Остання синхронізація: …».
4. Відкрий сайт на іншому пристрої, увійди тим самим акаунтом — дані підтягнуться.

**Якщо щось не так:**
* «Увімкни вхід через Google у Firebase Console» — не зроблено крок 2.1.
* «Додай цей домен у Firebase → Authorized domains» — не зроблено крок 2.2 або домен вписано з `https://` чи шляхом.
* «Немає доступу до бази — перевір правила Firestore» — не опубліковано `firestore.rules` (розділ 1).
* Вікно входу не відкривається — дозволь спливаючі вікна для сайту в налаштуваннях браузера. Вхід працює через спливаюче вікно; запасний вхід через перенаправлення в Safari й Firefox на GitHub Pages може не спрацювати (обмеження браузерів щодо сторонніх cookies, не застосунку).

### 2.5. (Необов'язково) Обмежити ключ Firebase

Ключ у `firebase-config.js` не секретний, але його можна обмежити, щоб ним не користувались інші сайти.

1. **https://console.cloud.google.com** → угорі обери проєкт **selfdev-47e40**.
2. Меню ☰ → **APIs & Services** → **Credentials** (Облікові дані).
3. У розділі **API Keys** натисни на ключ **Browser key (auto created by Firebase)**.
4. **Application restrictions** → обери **Websites** (HTTP referrers).
5. Натисни **Add** і додай **кожен** рядок окремо:
   ```
   https://flocky415.github.io/*
   https://selfdev-47e40.firebaseapp.com/*
   http://localhost:5173/*
   ```
   ⚠️ Рядок з `firebaseapp.com` обов'язковий — без нього перестане працювати вхід через Google.
6. Натисни **Save**. Зміни діють за кілька хвилин.

## 3. Розумний Джарвіз безкоштовно (Gemini + Cloudflare Worker)

### Як це влаштовано

* **Без налаштувань** Джарвіз відповідає з вбудованого «мозку»: знає твій прогрес, підказує наступний крок, виконує «додай звичку …» / «додай ціль …».
* **З проксі** — відповідає Gemini (ШІ від Google) з урахуванням твоїх завдань, цілей і серії. Ключ Gemini лежить на сервері Cloudflare і **не потрапляє** на сайт.
* Обидва сервіси безкоштовні: Cloudflare Workers — до 100 000 запитів на день, Gemini — безкоштовний рівень.

### 3.1. Отримати ключ Gemini

Старий ключ, який колись лежав у коді, вважай скомпрометованим — створи новий.

1. Відкрий **https://aistudio.google.com/apikey** і увійди Google-акаунтом.
   (Якщо відкриється стартова сторінка — натисни **Create or view a Gemini API Key**.)
2. Якщо там є **старий** ключ — наведи на нього, натисни ⋮ / 🗑 і видали.
3. Натисни **Create API key** (Створити ключ). Якщо попросить обрати проєкт — обери будь-який (можна створити новий).
4. Ключ з'явиться в списку. **Обов'язково обмеж його**, бо Gemini відхиляє ключі без обмежень:
   * наведи на позначку **Unrestricted** біля ключа → **Add restrictions**;
   * обери **Restrict to Gemini API only** → **Restrict key**.
5. Натисни на ключ → **Copy** (Копіювати). Ключ виглядає приблизно так: `AIza...` (39 символів).
6. Тимчасово встав його в Блокнот — знадобиться в кроці 3.3. Нікому не надсилай і не вставляй у файли проєкту.

> Не став обмеження **Websites / HTTP referrers** на цей ключ: запити йдуть із сервера Cloudflare, і з таким обмеженням ключ перестане працювати.

### 3.2. Створити Cloudflare Worker (проксі)

1. Відкрий **https://dash.cloudflare.com** і зареєструйся (безкоштовно) або увійди.
2. У лівому меню: **Compute (Workers)** → **Workers & Pages**.
3. Натисни **Create application** (Створити застосунок).
4. Обери варіант **Start with Hello World!** (або **Create Worker**).
5. У полі **Worker name** (Назва) впиши:
   ```
   jarvis-proxy
   ```
6. Натисни **Deploy** (Розгорнути). Cloudflare створить воркер із тестовим кодом «Hello World».
7. На сторінці воркера натисни **Edit code** (Редагувати код) — праворуч угорі.
8. Відкриється редактор із файлом `worker.js`. Виділи весь код (`Ctrl+A`) і видали.
9. Відкрий у проєкті файл **`jarvis-proxy/worker.js`**, скопіюй увесь вміст і встав у редактор.
10. Натисни **Deploy** (праворуч угорі) → підтверди **Save and deploy**.
11. Поверніся на сторінку воркера (стрілка «назад» або назва `jarvis-proxy` угорі).

### 3.3. Додати ключ і дозволений сайт

1. На сторінці воркера `jarvis-proxy` відкрий вкладку **Settings** (Налаштування).
2. Знайди розділ **Variables and Secrets** (Змінні й секрети) → натисни **+ Add** (Додати).
3. Перша змінна — ключ:
   * **Type** (Тип): **Secret**
   * **Variable name** (Назва): `GEMINI_API_KEY`
   * **Value** (Значення): встав ключ із кроку 3.1
4. Натисни **Add variable** (Додати ще змінну). Друга змінна — дозволені адреси:
   * **Type**: **Text** (звичайний текст, не Secret)
   * **Variable name**: `ALLOWED_ORIGINS`
   * **Value** (одним рядком, через кому, без пробілів і без шляху `/selfdev-app`):
     ```
     https://flocky415.github.io,http://localhost:5173
     ```
5. (Необов'язково) Третя змінна — модель:
   * **Type**: **Text**, **Variable name**: `GEMINI_MODEL`, **Value**: `gemini-3.8-flash`
   * Без неї використовується `gemini-3.6-flash` (стабільна модель). Список моделей: https://aistudio.google.com/docs/models
6. Натисни **Deploy** (Розгорнути) внизу розділу — без цього змінні не запрацюють.

### 3.4. Скопіювати адресу воркера й перевірити

1. На вкладці **Settings** → розділ **Domains & Routes** (або на головній вкладці воркера) знайди адресу виду:
   ```
   https://jarvis-proxy.<твій-нік>.workers.dev
   ```
2. Скопіюй її повністю.
3. Перевірка: відкрий цю адресу в браузері. Має показатися текст із `Method not allowed` — це **нормально** (воркер живий, просто чекає запитів від сайту).

### 3.5. Підключити воркер до сайту (GitHub)

1. Відкрий **https://github.com/flocky415/selfdev-app**.
2. Угорі репозиторію відкрий вкладку **Settings** (⚙️).
3. У лівому меню: **Secrets and variables** → **Actions**.
4. На вкладці **Secrets** натисни зелену кнопку **New repository secret**.
5. Заповни:
   * **Name**: `JARVIS_PROXY_URL`
   * **Secret**: адреса воркера з кроку 3.4, наприклад `https://jarvis-proxy.flocky415.workers.dev` (без `/` у кінці)
6. Натисни **Add secret**.
7. Якщо в списку є старий секрет **`GEMINI_API_KEY`** — натисни 🗑 біля нього й видали (він більше не потрібен, а без проксі ключ потрапляв би на сайт).
8. Перезапусти деплой: вкладка **Actions** → ліворуч **Deploy to GitHub Pages** → праворуч **Run workflow** → **Run workflow**.
   (Або просто зроби будь-який коміт у гілку `main`.)
9. Зачекай 1–2 хвилини, поки біля запуску з'явиться зелена галочка ✅.

### 3.6. Локальна перевірка (необов'язково)

У файлі `gemini-config.js` (він не потрапляє в репозиторій) заміни вміст на:

```js
const geminiConfig = {
  apiKey: "",
  proxyUrl: "https://jarvis-proxy.flocky415.workers.dev"
};
```

### 3.7. Перевірка й типові помилки

Відкрий сайт → натисни на Джарвіза (у робота — утримуй) → напиши «Що мені зробити зараз?». Відповідь має згадувати твої конкретні завдання.

| Що бачиш | Що зробити |
|----------|------------|
| «Проксі Джарвіза не пускає цей сайт 🔒» | У `ALLOWED_ORIGINS` неточна адреса: має бути рівно `https://flocky415.github.io` (без `/selfdev-app` і `/` у кінці). Після зміни — **Deploy**. |
| «Gemini не прийняв запит (код 400/403)» | Ключ без обмеження «Restrict to Gemini API only» або з обмеженням за сайтами (крок 3.1). Або в змінній `GEMINI_API_KEY` зайвий пробіл. |
| «Помилка від Gemini … not found (код 404)» | Неправильна назва моделі в `GEMINI_MODEL` — видали змінну або впиши модель зі списку. |
| «безкоштовний ліміт скінчився» | Ліміт Gemini на хвилину/день вичерпано. Джарвіз сам спробує ще раз; або зачекай. |
| Відповідає простими фразами, як раніше | Секрет `JARVIS_PROXY_URL` не додано або деплой не перезапущено (крок 3.5). Онови сторінку з `Ctrl+F5`. |
| `GEMINI_API_KEY is not set` | У воркері не додано секрет або не натиснуто **Deploy** після додавання (крок 3.3). |

## 4. Приватність коду — що це дає, а що ні

* Авторське право діє автоматично, а `LICENSE` («усі права захищено») прямо забороняє копіювати й використовувати код без твого дозволу.
* **Приватний репозиторій** ховає код від сторонніх, поки він лежить на GitHub.
* Але **застосунок, який відкривається в браузері, віддає свій JS кожному відвідувачу** — сховати його неможливо (F12 → Sources). Захищає від привласнення юридична сторона (LICENSE, дата комітів, авторство), а не приховування.
* GitHub Pages із безкоштовним акаунтом працює лише з публічних репозиторіїв. Для приватного репозиторію обери хостинг, який деплоїть із приватного репо (Firebase Hosting, Cloudflare Pages, Netlify).
* `<meta name="robots" content="noindex">` додано, щоб пошуковики не індексували сторінку.

## 5. Що змінилося для користувача

* **Дизайн:** нова тема з токенами, bento-головна, іконки в навігації, свайпи в списках, нижні панелі замість системних вікон, святкування рівня; оновлені всі вкладки (`design.css`, `ui.js`).
* **Джарвіз:** стоїть на підставці, стежить поглядом, кліпає, жестикулює, говорить відкритим ротом і підказує в бульбашках. Костюми: пірат, песик, котик, робот (маска відкривається натисканням, чат — утриманням), вікінг, смокінг. Підказки вимикаються в налаштуваннях Джарвіза на головній.
* **Синхронізація** між пристроями через вхід Google (`cloud-sync.js`).
* У `manifest.json` змінено `id` — уже встановлений застосунок (PWA) краще видалити і встановити заново. Нові версії файлів підтягуються автоматично (версія кешу в `sw.js`).
* XP, рівень і серії рахуються в браузері, тому «чесність» рейтингу друзів тримається на довірі.
* Chart.js і three.js підключені з CDN із закріпленою версією (`chart.js@4.4.7`, `three@0.160.0`). Для повної незалежності від CDN поклади файли в `vendor/` і зміни `src` в `index.html`.
* Локальні файли для перегляду (`design-preview.html`, `jarvis-skins/`, `.claude/`) — у `.gitignore` і на сайт не потрапляють.
